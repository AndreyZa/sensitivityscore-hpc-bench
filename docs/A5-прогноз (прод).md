# A5 — предрегистрированный прогноз на прод: PMU-мультиплексирование

Выжимка для дня ввода прод-стенда. **Прогноз зарегистрирован 20.07.2026,
коммит `c19a721` — ДО первой прод-серии**; полный вывод с методикой замера —
в «Аудит и план работ.md», §A5. Этот файл ничего не меняет в прогнозе, только
делает его находимым и проверяемым по шагам.

## Прогноз (для 3× Dell R760, 2× Xeon Platinum 8462Y+, SMT on)

Архитектурный PMU Intel даёт 8 программируемых счётчиков на ядро; при SMT они
делятся пополам → **4 на логический CPU** — ровно под конфигурацию агента
(LLC-пара + NUMA-пара = 4 события на под).

1. **`ss_agent_pmu_multiplex_ratio` = 1.000 на bench-узлах под серией** — при
   любом числе подов, пока PMU не пользуется никто, кроме агента. Алерт
   `SSPMUMultiplexed` молчит; кэш-ось валидна.
2. **Пятое событие на под стоит трети окна** (~0.67): любая добавка — третья
   ось на core-PMU, параллельный `perf`, Intel PCM, профилировщик — роняет
   долю в зону, где выводам по `llc_*` верить нельзя (по замеру дисперсии).
3. **Если SMT выключат** — 8 счётчиков на поток, запас на одну лишнюю пару.

Основание: плотность узла на мультиплексирование НЕ влияет (измерено на .72 —
cgroup-событие простаивающего пода счётчик не занимает; соперничают только
события одного пода), а 4 доступных счётчика на логический CPU дают долю окна
1.000 ровно до 2 пар и 4/2k при k>2 парах.

## Чем прогноз опровергается

Доля окна < 0.99 на спокойном прод-узле, где работает только агент. Это
означало бы < 4 доступных счётчиков (урезание в прошивке / PMU-виртуализация)
— тогда ДО серий: либо отказаться от NUMA-пары на core-PMU, либо перейти на
узловые (не-cgroup) счётчики для узлового давления, оставив cgroup-события
только для per-job метрик.

## Проверка в день ввода (по порядку)

```bash
make perfcheck-run        # доля окна при одном событии — ожидается 1.000
# затем под смоук-серией (STAND=prod make series SERIES=smoke):
#   ss_agent_pmu_multiplex_ratio в Prometheus — 1.000 на ВСЕХ bench-узлах
```

Результат проверки вписать сюда же (дата, узлы, доля) — прогноз со статусом
«подтверждён/опровергнут» уходит в диссертацию как пример предрегистрации.
