## 1. Тесты по энергопотреблению и доступ к железу

### Что уже решено (факты, не планы)

- Прод-стенд: **3× Dell PowerEdge R760** — 2× Intel Xeon Platinum 8462Y+
  (Sapphire Rapids), 64 ядра / 128 потоков, **2 NUMA-домена**, 384 ГБ RAM,
  bare-metal ([[Ввод прод-стенда (Этап 0)]] §4). RAPL и честный PMU доступны
  по построению; на STAGE (KVM) энергетика невыполнима — гейт прод.
- **PDU предоставляет партнёр** (решение 06.08) — закупки с нашей стороны нет.
- Стек Prometheus/Grafana уже развёрнут (ns `sensitivityscore-monitoring`),
  ClickHouse — точка правды, схема расширяется колонками энергии (план §4).
- ML-проба (`andreyza/mlprobe:dev`, коммит 88c2314) даёт вторую метрику
  эффективности — **Дж/инференс** — сверх Дж/задача Geant4.

### Чек-лист доступа — запросить у партнёра ДО фазы E0

| # | Что нужно | Зачем | Статус |
|---|---|---|---|
| Д1 | Модель PDU, подтверждение **per-outlet metering** и накопительного регистра кВт·ч | наземная истина энергии | ждём от партнёра |
| Д2 | Доступ SNMP/REST к PDU (креды, OID-набор) | `snmp_exporter` → Prometheus | ждём |
| Д3 | Карта **розетка ↔ узел** (+ обе розетки при двойных PSU) | атрибуция по узлам | составить при монтаже |
| Д4 | Доступ к BMC (IPMI/Redfish, DCMI power) | третий источник для кросс-валидации | запросить креды |
| Д5 | Root на узлах: powercap sysfs (RAPL), `perf_event_paranoid`, governor `performance` | атрибуция pkg/DRAM, контроль DVFS | вместе с вводом стенда |
| Д6 | PTP или дисциплинированный NTP | сведение окон энергии с epoch'ами серий | уточнить наличие |
| Д7 | Окно полного простоя стенда (часы) | idle-калибровка мощности узлов | согласовать |
| Д8 | Тариф на электроэнергию (день/ночь/пик), PUE ДЦ, при желании — фактор CO₂ | партнёрская модель §7 | явные входы партнёра |

### Какие тесты какой раздел статьи закрывают

| Фаза | Что даёт | Раздел статьи |
|---|---|---|
| E0 bring-up | кросс-валидация PDU↔RAPL↔IPMI, idle-калибровка | методика (доверие счётчикам — «статья счётчика» в буквальном смысле) |
| E1 близнецы + RAPL DRAM | **энергоцена интерференции** при фиксированной работе (H1) | центральный результат |
| E2 A/B/C на подписанном кластере | Дж/задача, EDP парно: SS vs default vs Trimaran (H2) | основное сравнение |
| E3 свип загрузки | энерго-Парето, точка пересечения «разнос/упаковка» (H3) | честные границы применимости |
| E4 энергоосознанная компонента | Парето-улучшение (H4) | «дальнейшая работа» статьи №1 либо ядро статьи №2 |
| E5 governor/нагрузки | внешняя валидность | обсуждение |

Минимальный состав статьи = **E0–E3**. Дисциплина та же, что в статье №1:
предрегистрация числовых прогнозов до прогонов, кластерный бутстреп по
повторениям, `energy-check` в paper-check (пересчёт несущих чисел из CH).

## 2. Сценарии использования (партнёрская рамка статьи)

| # | Сценарий | Ценность для партнёра | Чем подтверждается |
|---|---|---|---|
| U1 | **Харвестинг простаивающих мощностей**: доливка пакетных задач на недозагруженные узлы с интерференционным предохранителем | больше полезной работы на тот же кВт·ч; уплотнение не ломает SLA соседей | E3 (свип загрузки) + серии близнецов |
| U2 | **Энергоучёт на задачу**: Дж/задача, Дж/инференс — чарджбек, тендерные ТЗ, SLA с энергопунктом | измеренная, а не оценочная, себестоимость вычисления | E1/E2 (PDU-истина) + Kepler как per-pod оценка |
| U3 | **Тарифные окна и пик мощности**: сдвиг гибких серий в ночной тариф, срезание пиков заявленной мощности | прямые деньги без нового железа | регистры PDU + модель §7 (входы Д8) |
| U4 | **TCO/CO₂-отчётность**: кВт·ч/год, ₽/год, кг CO₂e/год с явными допущениями | одностраничник + живой дашборд Grafana | модель §7 плана, ΔЭ из E2 |
| U5 | (макс) **Энергоосознанный планировщик**: мультиобъектив интерференция × энергия | снятие натяжения «разнести/упаковать» на низкой загрузке | E4 |

Сквозная линия статьи: U1 — это ровно место, где вся индустрия упирается в
интерференцию (уплотнение бесплатно по CPU и дорого по диску/кэшу/сети), а у
нас есть измеренная цена этого «дорого».

## 4. Обзор существующих решений (каркас раздела related work)

Позиции ниже — навигация для написания раздела; перед вставкой в статью
каждую верифицировать по Crossref/сайтам, как это сделано в статье №1.

1. **Энергоосознанное планирование в оркестраторах.** Trimaran **Peaks**
   (жадный выбор по предельной мощности узла, модель P = K0 + K1·e^(K2·x) —
   разобрана по коду форка); KEIDS (Kubernetes-based energy and interference
   driven scheduler, IEEE IoT J. — ближайший по совмещению энергии и
   интерференции, проверить состав интерференционной модели); RL-co-scheduler
   [21 статьи №1]; энергоориентированный HPC co-scheduling — Zheng, Papka,
   Lan [22 статьи №1] — уже цитируется, прямой предшественник.
2. **Упаковка + гашение простоя.** Штатные скореры MostAllocated /
   RequestedToCapacityRatio, Trimaran TargetLoadPacking; Cluster Autoscaler /
   Karpenter (consolidation), Descheduler HighNodeUtilization, KEDA
   scale-to-zero; родословная — best-effort-уровень Borg. Ключевой аргумент
   раздела: упаковка без гашения почти не экономит (30–60 % пика на холостом
   ходу).
3. **Измерение энергии.** Kepler (eBPF + RAPL + модели, per-pod оценка),
   Scaphandre; энергоучёт Slurm (RAPL/IPMI-плагины); требования к отчётности
   производительности [35 статьи №1] — расширяем на ватты. Наш вклад здесь:
   трёхуровневая наземная валидация PDU↔RAPL↔IPMI с зарегистрированным
   порогом согласия.
4. **Со-локация и харвестинг.** Koordinator (линия Alibaba, QoS-классы,
   batch на возвращённых ресурсах), Katalyst (ByteDance), Crane (Tencent,
   предсказание + overcommit), Volcano (пакетные очереди); Harvest VMs
   (Microsoft), spot-механика облаков. Общая слепота — интерференция по
   неквотируемым ресурсам, наш U1.
5. **HPC power management.** Slurm powersave / power capping, EAR (BSC:
   пер-джобный DVFS с учётом MPI-фаз), GEOPM (Intel); исследования
   race-to-idle против DVFS — фон для нашего контроля governor.
6. **Углеродно-осведомлённое планирование.** Линия Google Carbon-Intelligent
   Computing (сдвиг во времени), carbon-aware KEDA; свежий обзор — arXiv
   2508.05949 (2026). Для российского контекста честнее говорить о тарифных
   окнах и пике мощности (U3), а CO₂ давать диапазоном.

**Разрыв, на который встаёт статья:** ни одна из позиций 1–6 не совмещает
измеренную модель интерференции по неквотируемым ресурсам с энергоцелью:
энергосистемы (1, 2, 5, 6) слепы к интерференции, со-локационные (4) режут её
грубыми QoS-классами без модели, KEIDS — ближайший сосед, но (проверить)
без двухкомпонентной цены и без наземной энергоистины. Наш вклад: (а)
измеренная **энергоцена интерференции** (RAPL DRAM на близнецах — E1); (б)
интерференционный предохранитель уплотнения (U1) с энерго-Парето (E3); (в)
методика наземного замера с кросс-валидацией трёх источников (E0).
